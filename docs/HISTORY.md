## Summary

Lightweight service for showing Claude/Codex activity on the Ulanzi TC001 running AWTRIX3. Original decomposition was six sub-projects A–F (protocol, Claude producer, Codex producer, Mac menu-bar app, server hardening, animated icons); A, B, C, D, E and Phase 2 (Unraid template + GHCR release pipeline) are all merged. Sub-project C (Codex producer + a `>_` identity across menu and clock) shipped as PR #18 + #19, 2026-05-21. Sub-project F (animated icons) folded into the new sub-project G — a full visual redesign of the AWTRIX render covering the icon pack plus rotation, preempt, display hold, context glass, and 5h-window bar. G decomposed into G.1a · G.1b · G.2 · G.3 · G.4; **all G slices now merged into `main` (PR #6/#8/#9/#11/#12/#13)**. G.4 was redesigned mid-flight from "5h-window bar" (data source unreachable) to a session-count bar on row 7 — server-only, no wire changes. A new **sub-project H — configurable display widgets** kicked off 2026-05-22: make the clock's signals menu-toggleable via the spine *menu checkbox → producer includes field → render-draws-if-present*. **H.1** (number-slot interleave of `X/Y` with a 5h rate-limit card) merged as **PR #20**, the **native settings window** (DarwinKit, replacing the osascript dialogs) as **PR #21**, **H.3** (statusline producer — lights the Claude rate card from `five_hour.used_percentage`) as **PR #22**, **H.2** (activity/approval detail — scrolling `Tool: detail` + a `cardTool` rotation card) as **PR #23**, and **H.4** (recent-activity trail — last-N actions ticker, Claude + Codex) as **PR #24**, all 2026-05-22. **The full configurable-display-widgets initiative (H.1–H.4 + the settings window) is now merged and device-verified.** The dev-Mac server was rebuilt from `feat/activity-trail` (H.2 render) so the activity field + trail actually render.

The project mirrors Anthropic's `claude-desktop-buddy` shape: AWTRIX clock = "Buddy" device, local agents per laptop = host-side bridge. AWTRIX3 firmware stays; we own both halves of the bridge.

1. **NSBitmapImageRep planes misuse** (commit `d6b768c`). `rgbaToImage` passed `&pix[0]` to `initWithBitmapDataPlanes:`, whose first arg is `unsigned char **` (a pointer to an *array of plane pointers*), so AppKit dereferenced the pixel bytes as a pointer → SIGSEGV on every open (fault address = the off-pixel colour `0xff0d0d0d…`). Fix: pass `nil` planes (AppKit allocates the buffer), copy pixels into `rep.BitmapData()`; also dropped the now-needless Go-buffer retention.
2. **NSTimer block freed before fire** (commit `04835f6`). With #1 fixed the window opened, then vanished ~1.6 s later. The rotation used `Timer_ScheduledTimerWithTimeIntervalRepeatsBlock`; DarwinKit backs the block with a **libffi closure that is freed before the delayed fire**, so the first tick crashed in `ffi_closure_SYSV_inner` (fault `0xa`, NULL CIF) *before the Go block body ran* (which is why a `DBG timer: tick` print never appeared). A timer-only headless repro crashed identically; a goroutine + `dispatch.MainQueue().DispatchAsync` per tick survived aggressive GC. Fix: drive rotation from a Go ticker goroutine that hops each tick to the main thread via DispatchAsync (a short-lived block, like the working initial window open), stopped on `windowWillClose`.

## Reusable Findings

- AWTRIX3 should remain the clock firmware for this project. The Claude Desktop Buddy firmware is M5StickC-oriented and would need hardware/display porting, while AWTRIX3 already exposes the right display primitives over HTTP.
- Node-RED is not a good fit for multi-session AI status aggregation. A small stateful service is clearer because it can own session expiry, prioritization, display rotation, and future laptop fan-in.
- For Homebrew Go installs, do not set `GOROOT` manually. Let `go env GOROOT` resolve to Homebrew's `libexec` path.
- The Buddy architecture (firmware + host bridge over BLE) is the correct mental model. Anthropic owns both halves; we own both halves of our equivalent (AWTRIX firmware exists; we build the host bridge ourselves). The local agent and the server are two distinct sub-systems with their own specs.
- Decomposing a "build feature X" task into A/B/C-style sub-projects with their own specs is the right move when the original plan hides interface contracts. Each sub-project gets its own spec → plan → implementation cycle, but they're loosely coupled through a single locked protocol.
- Hand-rolling protocol clients (MQTT 3.1.1, in this case) is rarely worth the "no deps" purity tax. The result lacked keepalive, reconnect, and QoS — a known-bad component. STYLE.md §11 reframed: "stdlib by default; deps that earn their slot are encouraged, not refused."
- Cross-reviewing prose deliverables (specs, style guides) with `codex exec` and `gemini -p` in parallel via stdin pipes is fast and high-signal. Both caught items the author missed; the union of their critiques is stronger than either alone. ~30 seconds of wall-clock per reviewer for a ~10 KB doc.
- Subagent-driven plan execution with two-stage review (spec compliance, then code quality) is reliable when the plan is bite-sized and the prompts include the full task text inline (don't make subagents read the plan file). Per-task follow-up commits for reviewer-flagged issues stay small and reviewable.
- For dev-loop Go testing in shells with stale `GOROOT=/Users/dt/.go`, prefix with `unset GOROOT &&`; subagent shells inherit cleanly but the controller's bash sometimes doesn't.
- **Producer↔server version skew is a silent failure mode.** When a feature's *render* lives in the server (e.g. H.1's rate card) but its *data* comes from a producer (e.g. H.3's `rate_window_pct`), shipping the producer alone shows nothing — the deployed server container must be rebuilt to a revision that has BOTH the wire field (#18) and the renderer (#20). Diagnose with `GET /version` (revision) vs the merge history; the lenient `/v1/status` decoder silently drops unknown fields, so an old server gives no error, just absence. After any render-side change, redeploy the dev-Mac container from current `main`.
- **A syntactically-valid-but-wrong config value defeats validation.** `STATUS_SERVER_URL=http://localhost:800` (typo for `:8080`) passed the settings-window URL validator (it only checks scheme+host) yet silently dropped every POST → empty `/state` → idle device. When "nothing shows," check the producer→server path early: `producer.env` URL, token match vs `~/.config/awtrix-ai-status/token`, and `/state` contents — before suspecting render code.
- **When recreating a live Docker container, `docker inspect` it first** to replicate exact run flags (mount destinations, command args, env var names) rather than reconstructing from memory — the real config mount was `/etc/awtrix-ai-status/config.json`, not the `/config.json` a guess assumed.
- **DarwinKit `Timer_ScheduledTimerWithTimeIntervalRepeatsBlock` (and long-lived blocks generally) crash when fired later.** DarwinKit backs a Go block with a **libffi closure** whose CIF/closure is freed before a *delayed* fire, so the timer's first tick crashes in `libffi ffi_closure_SYSV_inner` (fault `0xa`, NULL CIF) — *before the Go block body runs*, so no Go-side log line appears. Short-lived blocks that run immediately (e.g. the `dispatch.MainQueue().DispatchAsync` the initial window open uses) are fine; it's blocks that must survive seconds to a later callback that die. **Pattern: don't use NSTimer blocks for periodic UI; drive it from a Go `time.Ticker` goroutine that calls `dispatch.MainQueue().DispatchAsync(...)` each tick** (short-lived block, created-and-run immediately) and stop the goroutine on window close. Verified by a headless repro (`cmd/previewrepro`): timer-only → crash; goroutine+DispatchAsync → clean under GC pressure. `lldb --batch -o run -o bt` symbolicated the system frame (`ffi_closure_SYSV_inner`) — the key clue Go's own crash dump (just "signal arrived during cgo execution") hid.
- **DarwinKit/AppKit `NSBitmapImageRep` planes is `unsigned char **`, not the pixel bytes.** `initWithBitmapDataPlanes:` (DarwinKit `NewBitmapImageRepWithBitmapDataPlanes…`) expects a pointer to an *array of plane pointers*. Passing `unsafe.Pointer(&pix[0])` (the pixel buffer) makes AppKit dereference the first pixels as a pointer → SIGSEGV in cgo the instant the bitmap is read (the fault address is literally the pixel bytes, e.g. `0xff0d0d0d…`). Correct, lifetime-safe pattern: pass `nil` planes (AppKit allocates), then `copy(unsafe.Slice(rep.BitmapData(), w*h*4), pix)`. This also avoids retaining the Go buffer for AppKit. Crashed every preview-window open (PR #31) until fixed in `d6b768c`. Tell-tale in the crash log: `signal arrived during cgo execution` + a fault address that is recognisable pixel data.
- **A heartbeat that re-posts on file-existence (not process-liveness) keeps dead sessions alive and defeats every server-side staleness window.** The Claude producer's 10s tick re-POSTed any marker younger than the 6h file-TTL, refreshing the server `updated_at` so neither the 300s stale window nor the 30s done/error TTL ever fired for a *closed* session — it lingered up to 6h. Server staleness windows are a tolerance for **heartbeat failure**, not a closure detector; the producer must detect closure itself. `SessionEnd` is unreliable for this (best-effort; skipped on window-close / Cmd-Q / SIGHUP / crash — only graceful `/exit`·Ctrl-D fire it). The robust signal is **process liveness**: a hook subprocess's ancestry (`getppid()`, then walk *past* the `sh` wrapper, skipping shells + self) is the owning `claude`/`node` process; record its PID + `ps lstart` (the lstart guards PID reuse) in the marker and have the heartbeat reap when it dies (~10s). Keep such liveness fields **local to the marker**, out of the wire body — embed the wire struct so the POST decoder silently ignores them — and audit any code that round-trips the marker through the wire struct (the statusline `enrichMarker` did, silently stripping them every run). Fixed in `46366d4`.
- **Device-walk verification without waiting for real data:** read the live matrix with `GET http://192.168.0.14/api/screen` (flat list of 256 RGB ints, 32×8 row-major) and render it as ANSI 24-bit colour blocks to confirm pixels paint; then inject a crafted session with `POST /v1/status` (token from `producer.env`) to drive any widget to a chosen value (e.g. rate 75% for a visible bar), kept alive by a re-POST loop faster than the 25s running-staleness reap and `DELETE`d when done. Lets you demo specific on-device widget states deterministically. (First device walk where the server + producer binaries were *already current*, so flipping the `producer.env` toggles was the only step — always check `/version` revision + binary mtime before assuming a rebuild is needed.)
- **DarwinKit `NSWindow.delegate` (and weak AppKit refs generally) get garbage-collected → SIGSEGV on use.** A `WindowDelegate` created as a local and attached via `SetDelegate` has only a *weak* objc reference; once `openSettingsWindow` returns, Go GC frees the proxy, and the next `performClose:` → `windowShouldClose:` / `windowWillClose:` messages freed memory → SIGSEGV (`fault 0x6a`; 14× in the menu log before the fix, all in `Window.PerformClose`). **Fix: retain the delegate in a package-level var for the window's lifetime.** Same family as the NSTimer-block libffi and NSBitmapImageRep-planes crashes (PR #31): DarwinKit callbacks/objects must be kept alive Go-side. Bonus: prefer `w.Close()` over `w.PerformClose(nil)` for programmatic close (Close skips `windowShouldClose:`). Fixed in the Launch-at-login branch (`4acfd56`).
- **`launchctl enable/disable` does NOT reflect in System Settings → Login Items, and you can't drive that UI for a bundle-less LaunchAgent.** The macOS Login-Items / "Allow in the Background" toggles are the Background-Task-Management (BTM) database; `launchctl`'s disable-override is a separate layer, so toggling it leaves the System-Settings switch unchanged ("does nothing" from the user's view). There's no public API to flip another item's BTM state without shipping a real `.app` bundle + `SMAppService`. **For these bundle-less `~/Library/LaunchAgents` binaries, the user-meaningful "launch at login" control is install/uninstall** (installing registers the agent in BTM so it appears + launches; uninstalling removes it). That's why PR #32's checkbox became Install/Uninstall, not enable/disable.
- **Pure-Go SQLite (`modernc.org/sqlite`) keeps the distroless static build.** It needs no CGO, so `CGO_ENABLED=0` + `gcr.io/distroless/static-debian12:nonroot` still works (image stayed ~22 MB). For a writable, persistent DB as the **nonroot** user, use a **Docker named volume** (`-v awtrix-pomodoro:/var/lib/...`) over a host bind mount: a named volume mounted onto a path that exists in the image inherits that dir's ownership/permissions (the Dockerfile pre-creates `/var/lib/awtrix-ai-status` `--chown=nonroot`), so it's writable without host-uid wrangling. Open with WAL + `SetMaxOpenConns(1)` for a single-writer service, and **`Close()` it on shutdown** (checkpoints WAL, flushes in-flight writes). If a feature `os.Exit(1)`s on DB-open failure, a non-writable path will refuse to start the whole server — verify writability before enabling.
- **Building inside a git *worktree* hides the VCS revision from Docker `buildvcs`.** A linked worktree's `.git` is a *file* pointing outside the build context, so `go build -buildvcs=true` in the Docker build reports `version: unknown` and `scripts/image-smoke.sh`'s version check fails — even though the binary is fine. It resolves when built from a normal checkout / CI. Don't chase it as a code bug when building from `.claude/worktrees/...`.
- **Two branches that independently restructured the same AppKit file into different tab layouts won't auto-merge.** When `feat/pomodoro-app` and `feat/app-icon-tab` each rewrote `window_darwin.go` into an `NSTabView` (Status/Pomodoro vs Connection/Display/App), the merge conflicted only in that file. Cleanest resolution for an **un-visually-verifiable** AppKit file: `git checkout --theirs` the richer/more-recent layout as the base, then *graft* the other branch's delta (here: add a Pomodoro tab + the `openSettingsWindowOnTab`/`settingsTabView`/tab-index machinery) rather than hand-merging conflict markers. All non-window files (assets, components, menu wiring) merged cleanly. Deduplicate package-level vars both sides added (e.g. `settingsDelegate`).
- **`/admin/reload` silently reverts runtime-persisted settings unless the feature re-applies them.** Reload re-parses the config file and `cfg.Store`s it, overwriting any values a feature persisted at runtime (Pomodoro durations live in the SQLite settings table, not the file) and leaving the engine diverged from `cfg`. Fix: after the reload `Store`, have the feature re-sync (engine ← cfg) then re-apply its persisted blob. Read-modify-write on the `atomic.Pointer[Config]` is also a lost-update race vs a concurrent PUT (single-operator, accepted; would need a cfg-write mutex to close).
